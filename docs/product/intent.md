# 产品意图

> 状态：现行（2026-11-08，第三轮决策）。这是所有架构与交互设计的出发点；与本文冲突的设计以本文为准。

## 1. 一句话

**在 DSH 里做一个对标 Cursor Projects 的项目工作台：一个协调者统筹多个任务，每个任务可以选择由谁做（DSH 自己、Claude Code、Codex 等）、用什么模型、在哪里做（本地或云端）。**

## 2. 我们要成为什么

| 维度 | Cursor Projects（2026-09 Beta） | DSH Projects |
|---|---|---|
| 协调者 | 不写代码，规划、派发、收结果 | 相同；协调者固定是 DSH 原生会话 |
| 执行者 | 只有 Cursor 自己的 agent | **DSH 自身 + 外部 coding agent**（Claude Code、Codex、Gemini CLI、OpenCode、Cursor CLI…），统一接入 |
| 模型 | Cursor 精选模型 | 每个执行者可用的模型都能选；DSH 执行者覆盖 40+ provider 与自定义网关 |
| 执行位置 | 云端为主，需要时起本地 agent | **本地与云端对等**，云端是用户自己的算力（SSH 主机、Docker、E2B / Daytona 等） |
| 共享上下文 | 跨机器同步的一组文件 | Library（`context/`），对所有执行者、所有位置可见 |
| 交付 | 分支 + PR | 分支 + PR + 已验证的证据 |
| 订阅 | Slack、定时、PR | GitHub、飞书、定时（复用 DSH schedule / webhook） |

**差异化**：开放（任意 agent、任意模型）、自带算力（BYO cloud）、可验证（验证先于完成）。

## 3. 核心体验

1. 在协调者里说一句话，协调者拆成任务，并为每个任务推荐「谁做 · 什么模型 · 在哪做」。
2. 人在启动摘要里一眼确认或改掉这三项，然后放手。
3. 任务并行运行；任何执行者需要人时，问题或权限请求都汇到同一个托盘，一键回答。
4. 每个任务交回分支、PR 和验证结果；任务卡上永远看得到它由谁、用什么模型、在哪里跑的。
5. 任务可以在本地和云端之间移动：本地起头、云端跑完；或云端跑完、拉回本地调试。
6. 同一个任务可以让多个执行者 / 模型同时做（best-of-N），比较后采用一个。

## 4. 原则

1. **三个维度正交**：执行者（who）、模型（which model）、位置（where）互不绑定，每次运行把三者连同权限模式一起记成不可变的运行规格。
2. **对内一个协议**：外部执行者统一走 ACP；DSH 自己在本地走原生会话，在远端也走 ACP。不为每家 agent 写一套私有集成。
3. **agent 跟着代码走**：执行者进程必须运行在代码所在的位置；云端不是「远程文件系统」，而是「远程起 agent」。
4. **git 是交接介质**：本地与云端之间、执行者之间，只通过分支交接代码状态；会话能续接是增强，不是前提。
5. **凭据不出本机**：本地复用用户已登录的 CLI；云端只用用户显式提供的 API Key，按次注入；绝不把订阅登录态搬到云端。
6. **人永远看得见、拦得住**：所有执行者的过程可见，所有权限请求可由人审批；黑盒执行者在 UI 上明确标注。
7. 继承第二轮原则：单一真相、状态推导、验证先于完成、边界写在工具层、先存后做、只用宿主真实扩展点。

## 5. 不做什么（当前范围外）

- 不做托管云服务，不转售模型或算力；云端一律是用户自己的。
- 不中转 Claude / ChatGPT 订阅凭据。
- 协调者不可替换为外部 agent（它依赖 DSH 的工具与 UI）。
- 不做多人实时协作（Liveshare 只用于「看 / 接管某次运行」）。
- 不做 GPU 训练类任务的调度。

## 6. 待你拍板的决策

| # | 问题 | 选项 | 建议 |
|---|---|---|---|
| Q1 | 默认执行位置 | 本地优先 / 云端优先（Cursor） | **本地优先**；项目配置好云环境后，可把项目默认改为云端 |
| Q2 | 第一个云端底座 | SSH 主机 / Docker / E2B / Daytona | **先 SSH 主机 + Docker**（零外部依赖，复用 DSH ssh 包），再接一家沙箱：要原生 git API 选 Daytona，要内存级暂停选 E2B |
| Q3 | 首批外部执行者 | Claude Code、Codex、Gemini CLI、OpenCode、Cursor CLI | **Claude Code + Codex**（经 ACP 适配器），Gemini / OpenCode 因原生 ACP 顺带支持 |
| Q4 | 协调者的位置 | 只在本机 / 也能放云端 | **只在本机**（DSH 桌面所在处）；云端只跑 worker |
| Q5 | 订阅额度 | 本地允许复用 CLI 登录 / 一律 API Key | **本地允许复用、云端一律 API Key**，UI 标注计费来源 |
| Q6 | 厂商云（Cursor Cloud、Codex Cloud）作为黑盒执行位置 | 首版支持 / 延后 | **延后**，先把自带算力做扎实 |
